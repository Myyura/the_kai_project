### 题目描述

在图 1 的系统中，从主机 1 向主机 2 传送大小均为 $M$ 字节的数据包。路径中有两台高速交换机 SW1、SW2，且没有其他应用或主机产生的分组流量。主机间分组的单向时延为 $D$ 秒，三段链路带宽为 $B_1,B_2,B_3$，满足 $B_2<B_3<B_1$。

1. 为实现无差错数据传输，采用停等确认：主机 1 发出一个数据包，主机 2 收到后立即生成大小为 $m$ 字节的 ACK 并返回；主机 1 收到 ACK 后立即发送下一个数据包。已知

   $$
   \frac m{B_2}<\frac M{B_2}\ll D,
   $$

   忽略主机和交换机收发分组所需的处理时间，且上述两种响应延迟均为 0。求主机 1 到主机 2 的最大数据传输速率。
2. 在第 1 问系统中，每个数据包和 ACK 在传输途中均以概率 $\rho$ 随机丢失。主机 1 发包后若等待 $3D$ 秒仍未收到 ACK，就重传数据包；并假定超过 $3D$ 后 ACK 不会再到达。求一个数据包从主机 1 无误传至主机 2 所需时间的期望。
3. 通信开始时，主机 1 与主机 2 要同步一项可由单个分组承载的信息。考虑分组可能在链路中丢失，设计同步协议，并分别画出或列出两台主机应执行的状态转移图（或状态转移表）。
4. 第 1 问的停等方式在 $D$ 很大时吞吐率受限。提出两种提高数据传输速率的方法；对每种方法给出最大传输速率，以及达到该速率所需的条件。

## **Kai**

Use bytes/second for $B_i$, consistently with $M/B_i$ in the question. If bandwidth is instead specified in bits/second, replace each byte length by eight times that length. The bottleneck is $B_2$. The calculations below use independent packet losses between attempts and directions; marginal loss probability alone would not determine the retry distribution if losses were correlated.

### (1) Stop-and-wait throughput

A data packet takes $D$ to arrive and its ACK takes another $D$ to return. One cycle therefore carries $M$ bytes in $2D$ seconds:

$$
\boxed{R_{\mathrm{SW}}=\frac{M}{2D}\quad\text{bytes/second}.}
$$

The assumption $M/B_2\ll D$ makes this much smaller than $B_2$ and justifies neglecting serialization in this calculation.

### (2) Loss and retransmission

There are two different completion events, which the wording should distinguish.

**First correct reception at Host 2.** A data transmission succeeds with probability $1-\rho$. If it fails, the next attempt starts $3D$ later. If $N$ is the number of failed data transmissions before the first reception, then

$$
\Pr(N=k)=\rho^k(1-\rho),\qquad E[N]=\frac{\rho}{1-\rho}.
$$

Hence the latency literally until Host 2 first receives the data is

$$
\boxed{E[T_{\mathrm{receive}}]=D+\frac{3D\rho}{1-\rho}}.
$$

An ACK loss occurs after that first reception, so it does not change this event's time.

**Confirmed completion at Host 1.** To complete a stop-and-wait transaction, both the data packet and its ACK must arrive. An attempt succeeds with probability $p=(1-\rho)^2$. Each unsuccessful attempt costs $3D$; the final successful attempt costs $2D$. Thus

$$
E[T_{\mathrm{confirm}}]=(1-p)(3D+E[T_{\mathrm{confirm}}])+p(2D),
$$

and consequently

$$
\boxed{E[T_{\mathrm{confirm}}]=2D+3D\frac{1-(1-\rho)^2}{(1-\rho)^2}
=\frac{3D}{(1-\rho)^2}-D}.
$$

This second expression is the relevant cycle time for reliable acknowledged delivery and its long-run goodput is $M/E[T_{\mathrm{confirm}}]$. Retransmitted duplicates must be identified and acknowledged without delivering the application data twice. Both means diverge at $\rho=1$; at $\rho=0$ they reduce to $D$ and $2D$ respectively.

### (3) Synchronization protocol

Use a fresh session identifier $s$ and a monotonically increasing or otherwise fresh nonce $r$. A three-message exchange communicates the synchronization information $I_1,I_2$ and acknowledges both directions:

```text
Host 1                         Host 2
       SYN(s, I1)  ---------->
                 <----------  SYN_ACK(s, r, I2)
       ACK(s, r)   ---------->
```

Each control message fits in one packet. If only Host 1 has information to synchronize, $I_2$ can be empty. The identifier and nonce distinguish current replies from stale exchanges; control packets also include integrity checking. Use the following transitions (timeouts are greater than the normal round-trip time).

| Host 1 state | Event | Action and next state |
| --- | --- | --- |
| Idle | Start | Send `SYN(s,I1)`, start timer; enter WaitReply |
| WaitReply | Timeout | Retransmit the same SYN; restart timer |
| WaitReply | Matching SYN_ACK | Record $I_2,r$ once, send `ACK(s,r)`; enter Ready |
| Ready | Duplicate matching SYN_ACK | Resend ACK; remain Ready |
| Any | Stale or unrelated control packet | Ignore it |

| Host 2 state | Event | Action and next state |
| --- | --- | --- |
| Listen | Fresh SYN | Record $I_1$, choose $r$, send SYN_ACK and start timer; enter WaitAck |
| WaitAck | Duplicate matching SYN or timeout | Resend the same SYN_ACK; restart timer |
| WaitAck | Matching ACK | Stop timer; enter Ready |
| Ready | Duplicate matching SYN | Resend the retained SYN_ACK; remain Ready |
| Any | Stale or unrelated control packet | Ignore it |

A lost SYN is retried by Host 1, a lost SYN_ACK by either timer path, and a lost final ACK causes Host 2 to retransmit SYN_ACK, which Host 1 acknowledges again. Repeated messages do not reapply synchronization data. Subsequent data carries the session identifier and sequence number; it may also acknowledge $r$, so it can complete Host 2's transition if it arrives before the final control ACK. Under independent losses with $\rho<1$ and continued retries, establishment finishes with probability one. No finite handshake guarantees that both sides simultaneously know that the other knows completion when arbitrarily many packets can be lost; the protocol does not assume such a guarantee. This follows the retransmission and sequence-number principles of the [TCP state machine](https://www.rfc-editor.org/rfc/rfc9293.html).

### (4) Two ways to allow more outstanding data

Assume loss-free operation as in (1), sufficient sender/receiver/switch buffering, and full-duplex links (the small returning ACKs then do not consume forward-link capacity).

**Continuous sliding window.** Allow $W$ unacknowledged packets and slide the window as ACKs arrive. With the question's negligible serialization approximation,

$$
R_{\mathrm{window}}=\min\left(B_2,\frac{WM}{2D}\right).
$$

Thus the maximum is $B_2$, requiring approximately $WM\ge2DB_2$, enough sequence numbers and receive buffer, and a sender that keeps the bottleneck busy without overflowing the switches. Retaining serialization, use the actual packet-to-ACK round-trip time in place of $2D$; a small margin avoids a rounding-induced idle gap.

**Batch transmission with one cumulative block ACK.** Send a block of $K$ original-size packets back-to-back before waiting. The receiver acknowledges the complete block; sequence numbers or a bitmap identify missing packets if loss recovery is added. This is a batch protocol, whereas the sliding window can send a new packet after each intermediate ACK. Let

$$
\tau_0=2D+(M+m)\left(\frac1{B_1}+\frac1{B_2}+\frac1{B_3}\right)
$$

include serialization of the first data packet and the single ACK through store-and-forward switches. The last data packet follows the first by $(K-1)M/B_2$, so the block throughput is

$$
\boxed{R_{\mathrm{batch}}=
\frac{KM}{\tau_0+(K-1)M/B_2}}.
$$

It approaches the bottleneck maximum $B_2$ as $KM\gg2DB_2$ and the block is large relative to the finite serialization overhead. With any finite $K$ and positive waiting overhead it remains below $B_2$; continuous overlap of blocks removes this gap and leads back to a windowed scheme. Buffer capacity must cover a block, or the input must be paced to avoid queue overflow. Increasing the batch size does not require violating the specified individual packet length $M$.
