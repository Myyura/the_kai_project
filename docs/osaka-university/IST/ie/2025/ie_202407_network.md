# 大阪大学 情報科学研究科 情報工学 2024年7月実施 ネットワーク

## **Author**
祭音Myyura (co-authored with GPT 5.6 SOL)

## **Description**

TCPをトランスポート層に用いるHTTPについて答えよ。

### (1)

クライアントがHTMLファイルの先頭ビットを受信するまでのHTTPとTCPの挙動を、次の語句をすべて1回以上用いて説明せよ。

```text
HTTP Request、HTTP Response、SYNフラグ、ACKフラグ、
スリーウェイハンドシェイク、コネクション確立
```

### (2)

URL `http://www.ist.osaka-u.ac.jp/eng/image.jpg` を構成する `http`、`www.ist.osaka-u.ac.jp`、`/eng/image.jpg` の意味を述べよ。

### (3)

サーバがファイル送信後もTCPコネクションを維持するHTTPを考える。クライアントはファイル受信完了後、$S$ 秒ごとに制御メッセージを送り、サーバは受信時にカウントアップタイマを0へ戻し、タイマが $T$ 秒を超えない間コネクションを維持する。

- (3-1) クライアントからサーバ、サーバからクライアントへのアプリケーション層遅延がともに一定の $R$ 秒であり、制御メッセージの伝送遅延と処理時間は0とする。維持可能な $S$ の範囲を求めよ。
- (3-2) $S$ を小さく設定した場合にサーバで生じる問題を一つ述べよ。
- (3-3) ファイル送信後すぐTCPコネクションを解放するHTTPで、同一サーバの複数ファイルを取得すると完了時間が増える理由を説明せよ。

### (4)

HTTPで動画を順次取得・再生すると、TCPの挙動により再生が途切れることがある。理由を一つ述べ、それでもHTTPを用いる利点を一つ述べよ。

### 题目描述

本题考查HTTP over TCP：三次握手与请求/响应、URL结构、持久连接控制消息的周期约束、非持久连接开销，以及HTTP/TCP视频流中断原因与部署优势。

## **Kai**

### (1)

クライアントはSYNフラグを1としたTCPセグメントを送る。サーバはSYNフラグとACKフラグを1としたセグメントを返し、クライアントはACKフラグを1としたセグメントを返す。このスリーウェイハンドシェイクによりTCPコネクションを確立する。その後クライアントがHTTP Requestを送り、サーバがHTMLを含むHTTP Responseを返すため、クライアントはHTMLの先頭ビットを受信する。

### (2)

| 部分 | 意味 |
|---|---|
| `http` | 使用するスキーム／アプリケーション層プロトコル |
| `www.ist.osaka-u.ac.jp` | 資源を保持するサーバのホスト名（FQDN） |
| `/eng/image.jpg` | サーバ内の資源を指定するパス |

### (3)

#### (3-1)

サーバがファイル送信を終えてからクライアントの受信完了まで $R$ 秒、最初の制御メッセージ送信まで $S$ 秒、さらにサーバ到着まで $R$ 秒を要する。最初のタイマリセットまで $S+2R$ 秒であり、その後の受信間隔は $S$ 秒である。したがって

$$
\boxed{0<S\le T-2R},\qquad \boxed{T>2R}.
$$

#### (3-2)

制御メッセージが高頻度となり、サーバの処理負荷、帯域消費、および多数コネクションの管理負荷が増える。

#### (3-3)

ファイルごとにTCPのスリーウェイハンドシェイクが必要となり、そのRTTが累積する。また、各コネクションでふくそうウィンドウが初期化され、スロースタートを繰り返すためである。

### (4)

セグメント喪失時、TCPは再送が完了するまで後続データを順序通りアプリケーションへ渡さず、ふくそう制御で送信率も下げる。このため再生バッファが枯渇し得る。

一方、HTTPなら既存のHTTPサーバ、CDN、Webキャッシュを利用でき、NATやファイアウォールも通過しやすい。
