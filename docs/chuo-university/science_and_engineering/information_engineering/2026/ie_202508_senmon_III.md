## **Description**

問題Iは必答。問題II〜Vのうち、2問を選んで解答すること。

**問題III**

ネットワーク管理者のA氏は、自身が管理しているネットワーク機器をリレーショナルデータベースで管理している。以下はそのリレーションを示している。

R（<u>機種名</u>，<u>型式番号</u>，<u>製品番号</u>，種類，メーカー，サポートセンター連絡先，導入日，設置場所，<u>IPv4アドレス</u>）

※下線が引かれた属性は主キーを表しており、導入日を除くそれぞれの属性は文字列型、導入日は日付型である。

このリレーションには、「主キー → 非キー属性」の関数従属以外に、

- 機種名，型式番号，製品番号 → 導入日，設置場所
- 機種名，型式番号 → 種類，メーカー
- メーカー → サポートセンター連絡先

という関数従属が存在している。

このリレーションでは、<u>購入したばかりで未設置かつ未設定の機器を管理することができない</u>という問題を抱えている。

1. 下線部の問題が生じている理由を説明せよ。
2. リレーションRを第3正規形にせよ。それぞれのリレーションにおける主キーを下線で示すこと。なお、リレーションの名称はR1，R2，…のように付けること。
3. 第3正規形にしたリレーションに対して、192.68.10.0/24のネットワークに接続されている機器の「機種名，型式番号，製品番号，IPv4アドレス，設置場所」を取得するためのSQLを記述せよ。

小問3のSQLにより取得した機器とそれに関連する機器が下図のように接続されていたとする。

![ネットワーク構成とセグメントB](https://raw.githubusercontent.com/Myyura/the_kai_project_assets/main/kakomon/chuo-university/science_and_engineering/information_engineering/2026/ie_202508_senmon_III_network.png)

4. 破線で囲まれたセグメントBに接続可能なPC（パソコン）の台数を答えよ。ただし、ルータBを除きPC以外に接続されている機器はないものとする。

ある日にFS（ファイルサーバ）をリプレースしたところ、PC₁とPC₂からFSにアクセスできないという事象が発生した。それぞれのPCからインターネットには正常にアクセスできている。調査のためにPC₃からFSにアクセスしたところ、こちらは正常にアクセスできた。さらに、PC₁からFSに対してtracerouteコマンドを利用してアクセス確認を行った。その実行結果を下に示す。

```text
$ traceroute 192.168.13.100
192.168.13.100 へのルートをトレースしています
経由するホップ数は最大 30 です:
1  2 ms  2 ms  2 ms  192.168.11.1
2  3 ms  3 ms  3 ms  192.168.10.3
3  *     *     *
...
```

これらの調査結果をもとに、PC₁とPC₂からFSにアクセスできない原因となっている設定の誤りを特定した。その誤りを訂正したところ、PC₁とPC₂から正常にFSにアクセスできるようになった。

5. FSへのアクセス不具合について、原因となっている設定の誤りとして想定されるものを二つ挙げよ。

### 题目描述

问题 I 必答。从问题 II～V 中选择两题作答。

**问题 III**

网络管理员 A 使用关系数据库管理自己负责的网络设备，其关系如下：

R（<u>机种名</u>，<u>型号</u>，<u>产品编号</u>，种类，制造商，支持中心联系方式，导入日期，设置地点，<u>IPv4 地址</u>）。

带下划线的属性共同构成主键。除导入日期为日期类型外，其余属性均为字符串类型。

除“主键 → 非键属性”外，该关系还存在以下函数依赖：

- 机种名，型号，产品编号 → 导入日期，设置地点
- 机种名，型号 → 种类，制造商
- 制造商 → 支持中心联系方式

该关系存在以下问题：<u>无法管理刚购入、尚未安装且尚未配置的设备</u>。

1. 说明出现上述下划线部分问题的原因。
2. 将关系 R 分解为第三范式，给各关系命名为 R1、R2、……，并用下划线标出各关系的主键。
3. 针对第三范式关系，编写 SQL，获取连接到 192.68.10.0/24 网络的设备的“机种名、型号、产品编号、IPv4 地址、设置地点”。

假设由第 3 问的 SQL 获取的设备及其相关设备按上图连接。

4. 求虚线框内网段 B 可以连接的 PC 数量。假设除路由器 B 外，没有连接其他非 PC 设备。

某天替换 FS（文件服务器）后，PC₁、PC₂ 无法访问 FS，但这两台 PC 均可正常访问互联网。调查时发现 PC₃ 可正常访问 FS。从 PC₁ 对 FS 执行 traceroute，结果如下：

```text
$ traceroute 192.168.13.100
正在跟踪到 192.168.13.100 的路由
最大跳数为 30：
1  2 ms  2 ms  2 ms  192.168.11.1
2  3 ms  3 ms  3 ms  192.168.10.3
3  *     *     *
...
```

根据这些调查结果，管理员找到了导致 PC₁、PC₂ 无法访问 FS 的配置错误。修正后，两台 PC 均可正常访问 FS。

5. 列举两种可能导致 FS 访问故障的配置错误。

## **Kai**

### 1.

主キーには IPv4 アドレスが含まれている。主キーの各属性には `NULL` を許せないため、IPv4 アドレスが未割当ての機器について行を挿入できない。これは主キーの構成に起因する挿入異常である。

### 2.

与えられた関数従属に従い、例えば次のように分解する。

- R1（<u>機種名</u>，<u>型式番号</u>，<u>製品番号</u>，<u>IPv4アドレス</u>）
- R2（<u>機種名</u>，<u>型式番号</u>，<u>製品番号</u>，導入日，設置場所）
- R3（<u>機種名</u>，<u>型式番号</u>，種類，メーカー）
- R4（<u>メーカー</u>，サポートセンター連絡先）

R2では機器を識別する3属性が導入日・設置場所を決定し、R3では機種名・型式番号が種類・メーカーを決定し、R4ではメーカーが連絡先を決定する。それぞれの非自明な関数従属の左辺が当該関係のキーとなるため、第3正規形を満たす。

元の主キーを含むR1を残し、各分解時の共通属性が一方の関係のキーになっているので、元のリレーションを無損失結合で復元できる。また、与えられた関数従属を各関係で保持できる。未設定の機器はIPv4アドレスの行をR1に作らず、R2などに登録できる。

### 3.

小問3のアドレスは `192.68.10.0/24` と記載されている一方、後続の構成図は `192.168.10.0/24` を用いている。小問3の記載に従うSQLは次のとおり。IPv4アドレスは標準的なドット区切り十進表記で保存されているとする。

```sql
SELECT R1.機種名, R1.型式番号, R1.製品番号,
       R1.IPv4アドレス, R2.設置場所
FROM R1
JOIN R2
  ON R1.機種名 = R2.機種名
 AND R1.型式番号 = R2.型式番号
 AND R1.製品番号 = R2.製品番号
WHERE R1.IPv4アドレス LIKE '192.68.10.%';
```

構成図に示されたネットワークを取得する場合は、最後の条件を `LIKE '192.168.10.%'` とする。

### 4.

セグメントBは `192.168.12.0/24` であり、ホスト部は8ビット。ネットワークアドレス `.0` とブロードキャストアドレス `.255` を除くと、使用可能なホストアドレスは $2^8-2=254$ 個である。

このうちルータBのインターフェース `192.168.12.1` が1個を使う。PC用に利用できるのは `.2`〜`.254` なので、

$$
\boxed{254-1=253\text{ 台}}.
$$

ルータBのもう一方のアドレス `192.168.10.2` は別のサブネットに属するため、セグメントBのアドレス数からは差し引かない。

### 5.

FSと同一サブネットのPC₃からはアクセスでき、他のサブネットからの経路もルータCまでは到達している。したがって、FSのサブネット外への応答経路に関する設定を疑う。

1. **FSのデフォルトゲートウェイの未設定または誤設定。** 正しくはルータCのFS側インターフェース `192.168.13.1` を設定する。これが誤っていると、FSは `192.168.11.0/24` に属するPC₁・PC₂へ応答を返せないが、同一サブネットのPC₃には直接応答できる。
2. **FSのサブネットマスクの誤設定。** 正しくは `/24`、すなわち `255.255.255.0`。例えば `/16` にすると、FSは `192.168.11.x` も直結ネットワーク上にあると誤判断し、ルータに送らずARPで宛先を探してしまう。同一サブネットに実在するPC₃とは通信できても、PC₁・PC₂への応答に失敗する。
